## 目标概述

在不引入后端、保持单文件架构（index.html + state.json 同步）的前提下，完成以下增强：

1. 运输单：新增“货运公司”字段（下拉为主、支持新增），并支持运输单编辑。
2. 运输管理/库存联动：

   * 运输管理表格显示采购批次；

   * 优化“从库存生成运输单”：已生成运输单的库存批次不可再次选择；

   * 优化运输管理页“从库存生成”：在运输页直接选择“尚未生成运输单”的库存项并生成。
3. ISO 认证文件与供应商绑定：上传 ISO 文件时必须关联供应商；报价生成表格显示品牌（供应商）；生成报价 PDF 时若检测到供应商则仅展示匹配供应商的 ISO 文件并默认勾选。
4. 运输文件与运输单/采购批次绑定：上传运输文件时必须关联运输单号；该运输单关联采购批次；生成报价 PDF 时若检测到采购批次则仅展示关联批次的运输单号对应运输文件并默认勾选。

## 当前状态分析（基于仓库现状）

* 运输单数据：`transportRecords` 存在，记录字段为 `id/createdAt/trackingNo/method/status/freight/totalWeightKg/totalVolumeM3/lines[]`；`lines` 已包含 `inventoryId/batchNo/productId/vendor/...`（见 index.html:L4400-L4523）。

* 库存生成运输单：库存表格中有 checkbox 维护 `selectedInventoryForTransport`，生成按钮会调用 `openTransportCreateModalFromSelectedInventory()`，并在保存运输单后向对应库存项写入 `transportIds`（见 index.html:L4087-L4523）。

* 运输管理页已有“从库存生成”按钮，但当前依赖库存页勾选集合；在运输页本身无法挑选库存项（见 index.html:L953-L1011、L4451-L4472）。

* 公司级认证：`companyCerts.isoCerts / companyCerts.transportCerts` 当前仅存储 `id/name/path/size/sha256/uploadedAt`，上传入口 `openCertUpload(type)` 不带任何关联信息（见 index.html:L6715-L6799）。

* 报价生成：报价表 `quoteRows` 目前未显式存储供应商/产品ID；渲染列包含“采购批次”，但无“品牌/供应商”列（见 index.html:L228-L241、L3808-L4040）。生成报价 PDF 时会打开“选择附上认证文件”弹窗，渲染公司级认证 checkbox 不做匹配过滤/自动勾选（见 index.html:L7022-L7068）。

**UI**

**ISO 上传绑定供应商**

  * 上传 ISO 时要求必须选择供应商（或显式选择“未指定”，但默认应提示用户绑定以实现自动匹配）。

* `companyCerts.isoCerts[]` 的 entry 增加字段：

  * `vendor: string`

**报价 PDF 弹窗：ISO 自动匹配策略（按用户选择）**

### E. 运输文件上传绑定运输单号 + 按采购批次自动匹配

**运输文件上传绑定**

* 在“运输文件 (UN38.3/MSDS)”上传区域新增运输单选择控件：

  * 下拉来源：`transportRecords`（显示 trackingNo + 批次摘要）；

  * 上传运输文件时要求必须选择运输单。

* `companyCerts.transportCerts[]` 的 entry 增加字段：

  * `transportId: string`

  * `trackingNo: string`

**报价 PDF 弹窗：运输文件自动匹配策略（按用户选择）**

* 从报价行提取 `batchNo` 集合（非空、去重）。

* 计算“与报价批次相关的运输单集合”：

  * 规则：`transportRecords` 中任一 `line.batchNo` 与报价批次集合相交，则认为该 transportRecord 命中。

* 在弹窗中：

  * 若检测到批次集合且命中运输单非空：运输文件区域仅展示 `cert.transportId ∈ hitTransportIds` 的运输文件，并默认勾选；

  * 否则回退为展示全部运输文件，默认不额外勾选。

## 关键实现细节（避免踩坑）

* DOM 冲突：报价附件弹窗内部已使用 `qa-` 前缀的 id，应继续在弹窗根节点 `#cert-attachment-modal` 范围内 `querySelector`，避免与公司面板 DOM 重名。

* 兼容旧数据：所有新增字段（carrierCompany、vendor、transportId 等）必须视为可选；渲染时用空字符串兜底，避免 `undefined` 进入 UI。

* 原子同步：认证文件上传/删除仍走现有 GitHub commit 流程，新增绑定字段只影响 `state.json` 快照中的 `companyCerts` 元数据，不改变文件物理路径结构（仍为 `minova-data/certifications/{type}/{file.name}`）。

## 验证方式（本地 + 功能回归）

1. 运输单

   * 新建运输单：可选货运公司/新增货运公司，保存后在运输表格中显示；刷新后仍存在。

   * 编辑运输单：修改货运公司/明细重量体积/运费后保存，表格与搜索命中更新。
2. 库存联动

   * 库存中某批次生成运输单后，该批次 checkbox 变为不可选；删除该运输单后恢复可选（transportIds 被清理）。

   * 运输页点击“从库存生成”，能直接挑选“未生成运输单”的库存项并生成。
3. 报价表品牌列

   * 从库存选择加入报价后，品牌列自动带入供应商；手工也可改。
4. ISO 自动匹配

   * 上传 ISO 时绑定供应商；生成报价 PDF 弹窗里仅显示命中供应商的 ISO 文件且默认勾选。
5. 运输文件自动匹配

   * 上传运输文件时绑定运输单；报价行存在相关采购批次时，弹窗里仅显示命中运输单的运输文件且默认勾选。

## 假设与决策

* 弹窗策略按你的选择执行：只显示匹配 + 自动勾选；无匹配时回退展示全部。

* 货运公司采用：下拉为主 + 可新增；下拉选项从历史运输单去重生成，不额外引入新的全局配置表。

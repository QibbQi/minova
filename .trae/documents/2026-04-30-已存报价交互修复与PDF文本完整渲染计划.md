## Summary

本计划覆盖 5 个问题的修复与优化：
1. 删除已存报价后，下拉列表立刻移除对应项。
2. 新报价状态保存后，下拉列表立刻显示新保存项且选中，不出现空白。
3. 选择“-- 新报价 --”时弹窗提示清空内容；确认后跳转回报价单页并清空未存内容。
4. 加载历史报价后发生修改：下拉项名称后追加“（有修改）”；有修改时加载其它历史报价弹窗询问是否先保存，确认=覆盖保存当前报价后再加载，取消=直接加载目标报价。
5. 生成 PDF 时，备注/条款、预计时间表、支付条款等文本在 PDF 内自动换行并完整显示（提供比纯 CSS 更稳的方案）。

## Current State Analysis

- 已存报价（GitHub）逻辑集中在 [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html#L8750-L9062)：
  - 保存：executeSaveQuote 写入 index.json 与 quoteId.json，随后 refreshSavedQuotesList() 重新拉取并重建 select。
  - 删除：executeDeleteQuote 先提交删除，再 refreshSavedQuotesList()，然后 select.value=''。
  - 下拉 change：onSavedQuoteSelectChange 目前为空。
- 当前缺陷的主要根因：
  - 保存/删除后依赖“再读一遍 GitHub 的 index.json”来刷新 UI，存在短暂一致性/缓存导致的“下拉空白/未及时更新”体验问题。
  - 没有“已加载历史报价的脏状态（dirty）”跟踪，无法实现“（有修改）”标记与切换前保存提示。
  - html2canvas/html2pdf 对 textarea 等表单控件的渲染存在天然不稳定（换行/裁剪/overflow 处理不一致），仅注入 CSS 不能完全保证输出完整，需在 onclone 中把 textarea 替换为普通块级文本节点以稳定换行与高度计算。

## Proposed Changes

### 1) 统一渲染与本地缓存：renderSavedQuotesSelect + savedQuotesCache

修改文件：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html)

新增/调整的核心点：
- 增加一个纯渲染函数（不访问 GitHub）：
  - `renderSavedQuotesSelect(quotes, { selectedId, dirtyId })`
  - 输入 quotes 为 index.json 中 quotes 数组（已排序）；函数负责生成 `<option>`，并在 dirtyId 上追加“（有修改）”。
- 在 window 上维护两份轻量状态：
  - `window.__savedQuotesCache = { list: QuoteMeta[], byId: Map<string, QuoteMeta> }`
  - `window.currentSavedQuoteId`（已存在）+ 新增 `window.currentSavedQuoteName`
- refreshSavedQuotesList 的职责只做“拉取并更新 cache + 调用 renderSavedQuotesSelect”，不再在其它流程里强依赖二次拉取。

QuoteMeta 最小字段（复用现有 index.json）：
- id, name, customerName, quoteNo, createdAt, updatedAt, timestamp

### 2) 删除立即生效（问题 1）

目标：
- 点击删除确认后，成功提交后 UI 立刻移除对应 option，不需要等待再次读取 GitHub。

实现方式：
- 在 GitHub 分支 executeDeleteQuote：
  1. 读取 index.json 得到 list；
  2. 计算 nextList（剔除 quoteToDeleteId）与 nextIndex；
  3. commit 成功后，直接：
     - 更新 `window.__savedQuotesCache` 为 nextList；
     - 调用 `renderSavedQuotesSelect(nextList, { selectedId: '' })`；
     - 清理 `window.currentSavedQuoteId/currentSavedQuoteName` 与 dirty 状态；
     - 关闭删除 modal。
  4. commit 失败则 showToast，并调用 refreshSavedQuotesList() 回滚 UI（以远端为准）。

IndexedDB 分支保持现有 refreshSavedQuotesList()，并同样在成功后执行一次“就地 render”以立即反馈（可选，但推荐保持一致体验）。

### 3) 新报价保存后不空白且自动选中（问题 2）

目标：
- 在 select 为“-- 新报价 --”（value=''）时保存，保存成功后：
  - 下拉列表中立刻出现新条目；
  - 下拉自动选中新条目；
  - window.currentSavedQuoteId/name 同步更新；
  - 不依赖再次读取 GitHub 避免短暂空白。

实现方式：
- 抽取底层保存函数（GitHub/IndexedDB 都能调用）：
  - `saveQuoteInternal({ id, name, selectAfterSave }) -> { id, name, nextList }`
- executeSaveQuote 仅负责从 modal 取 name，然后调用 saveQuoteInternal。
- GitHub 保存成功后，使用“本次计算出的 nextList”直接 render：
  - `renderSavedQuotesSelect(nextList, { selectedId: id })`
  - 之后可异步/延迟再 refreshSavedQuotesList() 做一次校准（可选；默认不做，减少网络波动影响）。

### 4) “-- 新报价 --”切换确认 + 回到报价单页并清空（问题 3）

目标：
- 下拉选择 “-- 新报价 --” 时弹窗提示将清空内容；
- 确认后：
  - 回到报价单页（quote-page-select=1 + switchQuotePage('1')）；
  - 清空未存内容（复用 loadSavedQuote 在 id='' 分支的清空逻辑，或抽 `resetQuoteToBlank()` 供复用）；
  - 清理 currentSavedQuoteId/name、dirty 状态；
- 取消则恢复 select 到原值（不改变当前内容）。

实现方式：
- 实现 window.onSavedQuoteSelectChange：
  - 记录“变更前选中 id”（例如 `window.__lastSavedQuoteSelectValue`，在 refresh 渲染后也要同步更新）。
  - 当新值为 '' 时：
    - 弹 confirm；
    - 确认：执行回到页 1 + 清空 + 更新 lastValue；
    - 取消：select.value 回滚到 lastValue。
  - 当新值为非空：只更新一个“待加载目标 id”（不自动加载），保持当前“点击加载按钮才加载”的交互习惯。

### 5) Dirty 状态：下拉“（有修改）”+ 加载其它报价前保存确认（问题 4）

用户确认的规则：
- “（有修改）”只在下拉菜单临时显示，不写回 GitHub name。
- “确认保存”应覆盖更新当前历史报价（同 id）。
- 从历史报价切换到“-- 新报价 --”仅提示清空（不提供保存三选项）。

实现方式（事件驱动，避免昂贵 diff）：
- 新增全局状态：
  - `window.__quoteDirty = false`
  - `window.__suspendDirty = false`（apply snapshot / 批量赋值期间置 true）
- 统一设置脏状态的函数：
  - `setQuoteDirty(flag)`
    - 若当前有 currentSavedQuoteId 且 flag=true：
      - 更新 select 当前 option 文案追加/移除“（有修改）”
      - 可同时更新页面标题/某个 badge（仅在已存在 UI 元素时；本次不新增 UI，避免干扰）
- 绑定脏检测：
  - 在 `#pdf-content-wrapper` 上做事件委托监听 `input` 与 `change`：
    - 若 `window.__suspendDirty` 为 true 则忽略
    - 若 `window.currentSavedQuoteId` 存在且事件来源是 input/textarea/select/contenteditable，置 dirty=true
  - 在 applyQuoteSnapshot 完成后显式 `setQuoteDirty(false)` 并更新 lastValue/select 文案。
- 加载其它报价前提示保存：
  - 在 loadSavedQuote 开始处（读取 targetId 后，正式加载前）：
    - 若 `window.currentSavedQuoteId` 存在且 `window.__quoteDirty===true` 且 targetId 与 currentSavedQuoteId 不同：
      - confirm("当前报价已修改，是否保存后再加载？")
      - 确认：调用 `saveQuoteInternal({ id: currentSavedQuoteId, name: currentSavedQuoteName, selectAfterSave: false, silent: true })`，保存成功后再继续加载 targetId；保存失败则中止加载并提示错误（避免误丢数据）。
      - 取消：直接继续加载 targetId（丢弃未保存更改的语义由用户自行确认）。
  - 对 targetId==''（新报价）场景不走“保存确认”，遵循问题 3 的“仅提示清空”。
- 维护 currentSavedQuoteName：
  - 成功加载 quoteDoc 后，设置 `window.currentSavedQuoteName = q.name || 选项文案 || ''`
  - 成功保存后也同步更新。

### 6) PDF 文本完整渲染：onclone 替换 textarea 为 div（问题 5，更优方案）

目标：
- 彻底规避 html2canvas 对 textarea 渲染的换行/裁剪不一致：在克隆文档中把 textarea 替换为普通块级元素（div），用 textContent 绘制，确保：
  - 自动换行（含中文无空格场景）
  - 高度可自然扩展，避免只渲染一行或被 overflow-hidden 裁剪

修改点：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html#L8033-L8266) 的 confirmAndGeneratePDF → html2canvas.onclone

具体策略：
- 在 onclone 的末尾加入：
  - 遍历 `clonedDoc.querySelectorAll('textarea')`：
    - 创建 div：`div.textContent = textarea.value || ''`
    - 复制 className 与 id（保持 Tailwind 样式与现有选择器命中）
    - 强制追加稳定换行样式（inline style 优先级更高）：
      - `white-space: pre-wrap`
      - `overflow-wrap: anywhere`
      - `word-break: break-word`（如仍有中文长串不换行，再升级为 `break-all`，以确保“任何字符都可断行”）
      - `height: auto; min-height: 原 textarea 的计算高度或 1em`
    - `textarea.replaceWith(div)`
- 保留现有的 print/PDF 注入 CSS（@page、minHeight=297mm 等），作为兜底。
- 渲染前继续保留 `window.autosizeAllTextareas(cur)`，用于页面端编辑体验；PDF 端由替换 div 接管最终渲染可靠性。

## Assumptions & Decisions

- “加载”仍由按钮触发，不改为下拉自动加载（避免改变用户既有操作路径）。
- “（有修改）”仅 UI 临时提示，不写回 GitHub 的 index.json。
- “确认保存”覆盖更新当前历史报价（同 id）。
- 切换到“-- 新报价 --”仅提示清空；确认清空后回到报价单页并重置未存内容。
- PDF 文本完整性优先于与 textarea 像素级一致；PDF 中 textarea 将以 div 文本形式呈现，视觉上应保持一致但更稳定。

## Verification

在本地页面按以下步骤手动验收（无需改动仓库以外依赖）：
1. 连接 GitHub PAT 后，已存报价下拉立即显示历史记录。
2. 选择任一历史报价并点击删除：
   - 删除成功 toast 出现；
   - 下拉中该项立即消失，select 回到“-- 新报价 --”。
3. 选择“-- 新报价 --”并填写任意内容后，再次选择“-- 新报价 --”：
   - 出现“将清空内容”确认弹窗；
   - 确认后回到报价单页（page1），内容被清空。
4. “-- 新报价 --”状态点击保存：
   - 保存成功后下拉立即出现新记录并选中；
   - 不出现空白选项。
5. 加载某条历史报价后任意修改一个字段：
   - 下拉该条名称后出现“（有修改）”；
6. 在“（有修改）”状态下选择另一条历史报价并点击加载：
   - 弹窗询问是否保存；
   - 点击确认：先保存当前报价（同 id 覆盖），再加载目标报价；
   - 点击取消：直接加载目标报价。
7. 在条款/备注、预计时间表、支付条款中输入很长的中文连续文本（无空格），生成 PDF：
   - PDF 中文本自动换行；
   - 右侧不再截断，内容完整显示。

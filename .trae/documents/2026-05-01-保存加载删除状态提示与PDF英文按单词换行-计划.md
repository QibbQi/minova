## Summary

本计划实现两项改进：
1. 在已存报价的加载/保存/删除过程中，增加明显的状态提醒：`正在加载/保存/删除...，请稍等`，其中省略号动态变化（如 `.`→`..`→`...` 循环），在操作结束时自动消失并给出成功/失败提示。
2. 生成报价 PDF 时，备注与条款、预计时间表、支付条款等区域如果出现英文长文本换行，按“单词边界”换行，不把英文单词拆成字母分行（避免当前 PDF 渲染把英文切碎）。

## Proposed Changes

### 1) 增加“进行中”状态提醒（动态省略号）

修改文件：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html)

实现方式（不破坏现有 showToast 调用）：
1. 新增两个全局方法（基于现有 `toast-container`，不改 showToast 的签名）：
   - `window.startBusyToast(actionText)`：创建一个不会自动消失的 toast 元素，并通过 `setInterval` 动态更新省略号；返回 handle（包含 DOM 引用与 timerId）。
   - `window.finishBusyToast(handle, { type, msg })`：清理 interval，并将 toast 更新为成功/失败消息后淡出移除（或立即移除再调用 showToast）。
2. 文案规则：
   - 加载：`正在加载...，请稍等`
   - 保存：`正在保存...，请稍等`
   - 删除：`正在删除...，请稍等`
   - 省略号循环：`'' → '.' → '..' → '...'`，间隔 400–600ms（取 500ms）。
3. 接入点（确保 finally 清理）：
   - `executeSaveQuote`：调用 `startBusyToast('正在保存')`，在成功/失败后 `finishBusyToast`。
   - `loadSavedQuote`：在函数开头（确认 id 非空且将进行实际加载时）创建 busy toast；所有 return/throw 前统一进入 finally 关闭。
   - `executeDeleteQuote`：确认删除后进入 async 流程前创建 busy toast；成功/失败后关闭。

验收标准：
- 任一加载/保存/删除操作开始后，右下角出现“正在X...，请稍等”，省略号动态变化。
- 操作完成后该提示自动消失，并出现原有“成功/失败” toast（或 busy toast 自身变更为成功/失败并淡出）。

### 2) PDF 英文按单词断行（不拆字母）

修改文件：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html)

实现方式（保持现有 textarea→div 的“更稳渲染”框架不变，仅改断行策略）：
1. 修改 `onclone` 中 textarea 替换后的样式（替换掉 break-all/anywhere）：
   - `repl.style.whiteSpace = 'pre-wrap'`
   - `repl.style.wordBreak = 'normal'`
   - `repl.style.overflowWrap = 'break-word'`
   - `repl.style.hyphens = 'none'`
   - 说明：正常英文会在空格处换行；只有遇到超长无空格 token 才可能触发 break-word（极端情况），避免日常英文被拆字母。
2. 同步调整注入的 print CSS（当前对 `input, textarea` 设置了 `overflow-wrap:anywhere`）：
   - 将 `overflow-wrap:anywhere` 改为 `overflow-wrap: break-word`
   - 将 `word-break: break-word` 改为 `word-break: normal`
   - 增加 `hyphens: none`（对英文进一步避免断词/断字母的自动插入）
3. 覆盖范围：
   - 备注与条款 `#val-terms`
   - 预计时间表 `#val-step1/#val-step2/#val-step3`
   - 支付条款各阶段 `#lbl-confirmation/#lbl-installation/#lbl-testing/#lbl-final`
   - 这些都属于 textarea，会走统一替换逻辑。

验收标准：
- 在上述区域输入较长英文句子（带空格），生成 PDF 后换行发生在单词之间，不出现“一个单词被拆成两行字母”的情况。

## Assumptions & Decisions

- 状态提醒采用右下角 toast 形态（不遮罩页面），不改变现有点击流；PDF 生成的遮罩加载提示保持原样（已有 overlay）。
- 英文按单词断行优先；若出现极端超长无空格英文 token（例如超长 URL/序列号），允许 `overflow-wrap: break-word` 在必要时断开以避免 PDF 溢出裁切。

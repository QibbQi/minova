## Summary

本计划处理两项 UI/交互问题：
1. **支付条款**左侧阶段文案（确认后/安装后/测试与调试后/交付验收后）目前被固定宽度限制（`w-24`），导致单行显示过窄；调整为“左侧文案可尽量占满，宽度限制仅从数字（百分比/金额）区域开始”。
2. 点击“+ 增加阶段”显示“最终阶段”后，左侧可能出现空白；调整为：显示时自动填充默认文案且可编辑（textarea），避免空白无字。

## Current State Analysis

### 支付条款布局现状

- 支付条款每行使用 `flex justify-between items-center ...`，左侧文案是 textarea 且固定 `w-24`：
  - 例如 [index.html:L203-L248](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html#L203-L248)
  - `#lbl-confirmation/#lbl-installation/#lbl-testing/#lbl-final` 均是 `<textarea ... class="w-24 ...">...`
- 右侧数字区域（百分比 + 金额）也有固定宽度 `w-24`（金额）：
  - [index.html:L205-L234](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html#L205-L234)
- 由于左右都固定宽度 + `justify-between`，左侧文案无法向右扩展，导致视觉上“单行文字显示太窄”。

### “+ 增加阶段”显示后左侧空白的触发点

- 点击按钮调用 `toggleFinalPayment(true)` 显示 `#payment-final-container`：
  - [index.html:L3909-L3923](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html#L3909-L3923)
- 当前 `toggleFinalPayment(true)` 仅做显示/隐藏，不会在显示时确保 `#lbl-final` 有默认值或 placeholder，因此当其 value 为空时会出现“左侧无字”。
- 现有 `#lbl-final` 是 textarea，符合“可修改文字”的需求，但需要在显示时补齐默认文案与可编辑体验。

## Proposed Changes

### 1) 支付条款：调整每行布局，限制从数字区域开始

修改文件：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html)

修改点（以每个 payment row 为单位，4 行一致处理）：
1. 将行容器从 `flex justify-between ...` 改为更可控的分区布局：
   - 行容器：`flex items-center gap-2`
   - 左侧文案容器：追加 `flex-grow min-w-0`
   - 右侧数字容器：追加 `flex-shrink-0` 并给一个固定宽度（例如 `w-[190px]` 或使用现有金额 `w-24` + 百分比输入/按钮自然撑开）
2. 将 `#lbl-confirmation/#lbl-installation/#lbl-testing/#lbl-final` 的 textarea class 从 `w-24` 改为 `w-full`：
   - 保留 `uppercase/resize-none/overflow-hidden` 与 autosize oninput，确保仍为可编辑且高度自适应。
3. 保持金额栏 `w-24 text-right` 不变，使“限制从数字前开始”稳定落在数字区域。

预期效果：
- 左侧文案可利用可用空间，单行可显示更多字符；数字区域宽度保持稳定对齐。

### 2) “+ 增加阶段”：显示最终阶段时确保左侧默认文案可编辑

修改文件：
- [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-%E4%B8%AA%E4%BA%BA/Github%20Project/minova/index.html)

修改点：
1. 在 `toggleFinalPayment(true)` 分支中：
   - 获取 `#lbl-final` textarea
   - 若其 `value.trim()` 为空：
     - 中文：填入 `交付验收后`
     - 英文：填入 `Upon Handover`
   - 调用 `autosizeAllTextareas(container)` 或对该 textarea 触发一次 autosize
2. 为 `#lbl-final` 增加 placeholder（仅作为兜底，不改变已有 value）：
   - placeholder 中文/英文可复用同一默认文案，或由 `updateLanguageLabels()` 在切换语言时统一设置（推荐）。
3. 若需要与语言切换保持一致：
   - 在 `i18n` 增加一个键（如 `paymentFinalDefault`），由 `updateLanguageLabels()` 写入 placeholder，并由 `toggleFinalPayment(true)` 在 value 为空时填充。

预期效果：
- 点击“+ 增加阶段”后，左侧不会出现空白；且文案可立即编辑。

## Assumptions & Decisions

- 不改变支付条款的计算逻辑（`onPaymentPercentInput/calculateQuote` 等）；仅调整 DOM 布局与默认文案补齐。
- 仅对支付条款区域做布局调整，不改动预计时间表区域。
- 默认最终阶段文案：
  - 中文：交付验收后
  - 英文：Upon Handover

## Verification

1. 支付条款宽度
   - 将 `#lbl-testing` 填入较长中文（例如 15~25 字），确认单行可显示更多字符且不会被固定宽度过早截断。
   - 数字区域（百分比输入与金额）仍右对齐且列宽稳定。
2. 增加阶段默认文案
   - 清空 `#lbl-final` 的值（或加载一个其值为空的报价），点击“+ 增加阶段”：
     - 期望：左侧自动出现默认文案，且可编辑。
   - 切换语言后重复验证默认文案与 placeholder 是否符合当前语言。

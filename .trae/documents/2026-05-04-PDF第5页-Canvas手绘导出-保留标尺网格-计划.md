## Summary

为解决报价 PDF 导出时 SITE OVERVIEW（第 5 页）仍缺失「测距线/面积多边形/自定义组件形状」且「背景比例不一致」的问题，本计划将第 5 页导出从 “DOM → html2canvas 截图” 进一步升级为 **Canvas 手绘合成快照**：

- 导出时根据 `siteOverview` 的真实数据（背景图、modules、自定义 points、多边形 area、dist 测距、标尺/网格设置）在离屏 canvas 上绘制。
- 生成一张 **包含标尺+网格+画布内容** 的图片（dataURL），并只在 PDF 导出时将该图片注入到导出 clone DOM（不改动真实页面 DOM）。

这样可彻底绕开 html2canvas 对 `clip-path`、SVG marker/defs、复杂叠加层的兼容性问题，保证第 5 页输出与编辑器一致，同时不影响其他页面与正常交互。

## Proposed Changes

### 1) 新增导出专用 Canvas 渲染器（只用于 PDF 第 5 页）

**文件**： [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html)

**新增函数（建议命名）**

- `buildRoofSnapshotForPdfCanvas(): Promise<string>`
  - 返回 `data:image/png`（推荐 PNG，避免线条/文字 JPEG 压缩糊；如体积过大再切回 JPEG）。

**Canvas 尺寸与布局（保留标尺+网格）**

- 目标导出区域选择 `#roof-editor-grid` 的视觉尺寸：
  - canvasWidth/Height = `roof-editor-grid.getBoundingClientRect().width/height`
  - 标尺占位固定为 20px（与现有布局一致，grid-template 20px 规则可直接使用）。
  - viewport 区域 rect：`{ x: 20, y: 20, w: width-20, h: height-20 }`

**绘制顺序（确保可视一致）**

1. 背景填白
2. 绘制标尺（X/Y tick + 数字）
3. 绘制网格线（与当前 gridStep 设置一致）
4. 绘制背景图
   - 使用真实 `roof-image` 的 `naturalWidth/naturalHeight` + viewport w/h 做 contain 计算（等价于 getImageRect 的逻辑）
   - 确保左上对齐（x=0,y=0），并把结果映射到 viewport 区域（加上 20px 偏移）
5. 绘制组件
   - PV：矩形填充 + 描边（颜色/透明度使用现有 settings.moduleOpacity）
   - Custom：
     - 若 `m.points` 存在（顶点编辑形状）：按 points 绘制 polygon
     - 否则按 `shape` + `getCustomShapePointsFromRect()` 得到 polygon
     - 填充色：`m.bgColor`（hexToRgba + moduleOpacity），描边使用与现有 UI 一致的 rgba
6. 绘制标注（测距/面积）
   - dist：画线 + marker/arrow（复刻 drawMarker/drawArrow/drawDist 的几何，但用 canvas path）
   - area：polygon fill（opacity）+ stroke
7. 绘制数字胶囊（保持黑色 pill）
   - dist：中点处绘制黑色圆角矩形 + 白字（`formatDistanceM`）
   - area：质心处绘制黑色圆角矩形 + 白字（`formatAreaM2` 或现有面积显示格式）

**坐标换算复用**

- 复用现有 `getImageRect()` / `getPxPerM()` / `worldToPx()` 思路，但在导出函数中创建一个 “exportRect”：
  - `exportRect` 的 `vw/vh` 使用 viewport 的像素 w/h（width-20,height-20）
  - `worldToPxExport(xM,yM)` = `worldToPx(xM,yM)` 的结果再加上 viewport offset（+20,+20）
  - 这样导出位置与编辑器完全一致。

### 2) PDF 导出流程仅在第 5 页切换为 Canvas 快照注入（不影响其他页面）

**改动点**

- 在逐页循环中，当 `pageNum===5`：
  - `window.__pdfRoofSnapshotDataUrl = await buildRoofSnapshotForPdfCanvas()`
  - 其它页保持原逻辑与原 onclone 处理不变
- `onclone` 分支继续使用 `__pdfRoofSnapshotDataUrl` 注入 clone，但注入目标保持为 page 5 的 `#roof-viewport` 或 `#roof-editor-grid`（二选一）：
  - 若快照包含标尺+网格，建议注入到 `#roof-editor-grid` 并覆盖整个 grid 区域
  - 同时确保 clone 中被覆盖区域的 `position` 为 relative，img 绝对定位铺满

### 3) 安全与不影响交互的保证

- `buildRoofSnapshotForPdfCanvas()` 只读 `siteOverview/roofBackground/modules/measurements/settings` 与 DOM 的尺寸/图片 naturalWidth，不修改任何状态与 DOM。
- `onclone` 只修改导出 clone DOM，不影响页面真实 DOM。
- 导出结束清空 `window.__pdfExportingPageNum/__pdfRoofSnapshotDataUrl`。

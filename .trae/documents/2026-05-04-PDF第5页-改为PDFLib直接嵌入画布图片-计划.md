## Summary

你确认「PDF 第 5 页只要画布」后，最稳妥的修复方式是：**跳过 html2pdf 对第 5 页的二次截图**，改为在导出时把“画布全区（含标尺/网格/组件/测距线/面积）”先合成为一张高分辨率图片，然后用 **PDFLib 直接把图片嵌入到 A4 页**。

这样可以同时解决你当前看到的所有症状：

- 线/面积/自定义顶点形状在 HTML→Canvas→PDF 的二次截图过程中被丢失/变形（现在只需要一次合成）
- 画布被裁切（PDFLib 以比例 fit 到 A4，永不裁切）
- 背景比例不一致（合成阶段使用与编辑器一致的 contain 逻辑，PDF 再按比例放入 A4）
- 不影响其他页面与正常使用（仅替换导出流程中 page 5 的生成方式）

## Current State Analysis

- 当前导出流程是：逐页隐藏/显示 → `html2pdf().from(#pdf-content-wrapper)` 生成临时 PDF → PDFLib 合并。
- 现有代码已经在“附件合并”阶段使用 PDFLib 直接把图片嵌入 A4（`embedPng/embedJpg + ratio fit`），证明该路径在本项目中可行。
- 当前即使我们做了第 5 页 Canvas 合成，仍会被 html2pdf 再截图一次（双重光栅化），容易造成细线/半透明面/形状边界在最终 PDF 里“看不到/退化”。

  - 自定义顶点形状边缘更清晰

### 2) 导出循环里：pageNum===5 不再走 html2pdf，而是用 PDFLib 直接加页

**目标**

- 其它页（1-4）保持原逻辑（html2pdf → 临时 PDF → mergedDoc copyPages）。
- 第 5 页（画布页）改为：
  1) `const dataUrl = await buildRoofSnapshotForPdf()`（PNG）
  2) `const bytes = base64ToUint8Array(dataUrl)`（新增工具函数）
  3) `const img = await mergedDoc.embedPng(bytes)`
  4) `const page = mergedDoc.addPage(A4)`
  5) 用比例 fit（与附件图片的 drawImage 逻辑一致）把画布铺满 A4（建议留 0~10px 边距）

**关键实现细节**

- 新增 `dataUrlToBytes(dataUrl)`：
  - `const b64 = dataUrl.split(',')[1]`
  - `const bin = atob(b64)` → `Uint8Array`
- ratio fit：
  - `ratio = Math.min(pw / imgW, ph / imgH)`（如要留边距则 `pw-40/ph-40`）
  - `page.drawImage(img, { x:(pw-w)/2, y:(ph-h)/2, width:w, height:h })`
- page 顺序：保持与 selectedPrintPages 的顺序一致（遇到 5 时在对应位置 addPage 即可）。

### 3) 删除或禁用第 5 页的“onclone 注入快照”分支（避免重复逻辑）

  - `window.__pdfExportingPageNum/__pdfRoofSnapshotDataUrl` 对 page 5 可以不再使用
  - `onclone` 中的 `useRoofSnap` 分支可以保留但不会触发，或加判断直接 return

### 4) 验证与回归

- 第 5 页画布准备：至少 1 条 dist、1 个 area、1 个 edit vtx 自定义组件。
- 导出 PDF：

  - dist 线/端点可见、area fill+stroke 可见
  - 自定义组件按顶点编辑后的形状导出（非矩形）
- 其它页（1-4）导出不变且可正常查看。
- 导出结束后返回页面继续编辑，Site Overview 工具不受影响。

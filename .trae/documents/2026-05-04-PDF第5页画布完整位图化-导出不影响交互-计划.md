## Summary

为解决「报价 PDF 导出时 SITE OVERVIEW（第 5 页）画布内容不完整/比例不符/测距线与面积消失/自定义组件形状丢失」问题，本计划将第 5 页导出改为 **导出专用的“画布位图化”路径**：在导出前把画布（背景 + 网格/标尺 + PV/自定义组件 + 测距线/面积 + 标签）渲染成一张图片，然后在 PDF 导出时仅把这张图片注入到 PDF 的克隆 DOM 中。

该方案满足约束：

- 不影响其他页面（只对 PDF 导出第 5 页生效）。
- 不影响导出过程中其他页面查看（仍沿用现有逐页生成机制）。
- 不影响 Site Overview 工具正常使用（不再改动/隐藏真实 DOM，仅改导出时的 clone DOM）。

## Current State Analysis（基于仓库代码现状）

- PDF 导出入口：`window.confirmAndGeneratePDF`：[index.html:L8605-L9012](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html#L8605-L9012)
- 当前第 5 页策略：在导出循环里用 `html2canvas(#roof-editor-grid)` 生成 dataURL，然后在真实 DOM 上叠加 overlay 并隐藏 `#roof-viewport` 等，再让 `html2pdf` 截图（见 [index.html:L8836-L8950](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html#L8836-L8950)）。
- 用户现象：
  - 背景图比例不符（需要完整展现上传图，且与画布中一致）。
  - 测距线/面积多边形消失，只剩浮动数字（说明 SVG/路径未被位图化捕获）。
  - 只有 PV 组件正常，自定义组件只剩白色文字（clip-path/自定义形状未被捕获）。
- 根因推断：
  - html2canvas 对 `clip-path`、复杂 SVG（marker/defs/路径）存在兼容缺口，导致“线/多边形/自定义形状”渲染缺失，而 HTML label 仍可被截图到。
  - 在真实 DOM 上做临时隐藏/overlay 叠加，仍可能在导出过程中引入布局差异，从而导致“比例偏差”，并存在影响交互的风险。

## Proposed Changes

### 1) 将“第 5 页位图化”迁移为导出专用的 clone 注入（不操作真实 DOM）

**目标**

- 导出第 5 页时：`html2pdf` 截到的是一个单一 `<img>`（画布快照），而不是复杂的多层 DOM。
- 页面运行时：不插入 overlay、不隐藏 viewport，不影响工具正常使用。

**实现**

- 在 `confirmAndGeneratePDF` 的逐页循环中：
  - 在调用 `html2pdf().from(container)` 之前设置全局变量：
    - `window.__pdfExportingPageNum = pageNum`
    - `window.__pdfRoofSnapshotDataUrl = (pageNum===5 ? await buildRoofSnapshotForPdf() : '')`
  - 移除当前“真实 DOM overlay + visibility hidden”逻辑（[index.html:L8888-L8950](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html#L8888-L8950)），避免影响交互与布局。

- 在 `opt.html2canvas.onclone(clonedDoc)` 中增加第 5 页分支：
  - 读取 `window.__pdfExportingPageNum` 与 `window.__pdfRoofSnapshotDataUrl`
  - 当且仅当 `pageNum===5 && dataUrl`：
    - 定位 clone 内的 `#roof-editor-grid`（或 `#roof-viewport`）并替换为 `<img src=dataUrl>`（或把原内容 `display:none` 并插入 img）。
    - img 样式：`width:100%; height:100%; object-fit:contain; display:block;`
    - 这样 html2pdf 截图只会捕获位图，稳定输出。

### 2) 构建“可被 html2canvas 正确位图化”的画布快照（解决线/多边形/自定义形状缺失）

核心思想：在生成快照前，先创建一个“导出专用的临时克隆画布”，将难以截图的元素转换为更易截图的形式，再对这个临时画布执行 html2canvas。

**新增函数：`buildRoofSnapshotForPdf()`（返回 dataURL）**

步骤（同步/异步组合）：

1) 确保第 5 页处于可渲染状态
   - `renderRoof()`（已有）
   - `await 2x requestAnimationFrame` 确保布局稳定（已有类似逻辑）。

2) 创建离屏容器并挂载临时克隆（确保 CSS 生效）
   - `const host = document.createElement('div')`
   - `host.style.position='fixed'; host.style.left='-100000px'; host.style.top='0'; host.style.width='0'; host.style.height='0'; host.style.overflow='hidden'`
   - `const clone = roofEditorGrid.cloneNode(true)`（包含标尺+viewport+各图层）
   - `host.appendChild(clone); document.body.appendChild(host)`

3) 在临时克隆内做“导出兼容性转换”

**3.1 背景图比例一致**

- 对 clone 内 `#roof-image` 做显式尺寸/定位（与页面显示一致的 contain）：
  - 读取 `img.dataset.iw/ih` 或 naturalWidth/naturalHeight
  - 用 clone 内 `#roof-viewport` 的 `getBoundingClientRect()` 计算 vw/vh
  - `s=min(vw/iw, vh/ih)`, `w=iw*s`, `h=ih*s`
  - 设置 `img.style.width/height/left/top` 并 `objectFit='contain'`、`objectPosition='left top'`

**3.2 自定义组件形状可见**

- 遍历 `.pv-module.is-custom .pv-module-shape`：
  - 读取其 `style.clipPath`/computed clipPath：
    - 若 `polygon(...)`：解析百分比点集 → 用 inline SVG `<svg viewBox="0 0 100 100" preserveAspectRatio="none"><polygon .../></svg>` 替换 shapeDiv
    - fill/stroke 取 computedStyle 的 backgroundColor/borderColor/borderWidth（与当前 onclone 的转换逻辑保持一致）
  - 目标：让 html2canvas 捕获 SVG 多边形，而不是 clip-path。

**3.3 测距线/面积多边形可见**

- html2canvas 对 SVG 兼容不稳定（用户现象），因此把 `#roof-measure-layer` 内的 SVG 转成 img：
  - 在 clone 中找到 `#roof-measure-layer svg`
  - `const xml = new XMLSerializer().serializeToString(svg)`
  - 构造 data URL：`data:image/svg+xml;charset=utf-8,${encodeURIComponent(xml)}`
  - 用 `<img>` 替换该 svg：
    - `img.style.position='absolute'; inset:0; width:100%; height:100%`
  - 保留原来的 HTML label（浮动数字）以保证文字位置一致。

4) 对临时克隆执行 html2canvas 得到位图
   - `const canvas = await html2canvas(clone, { scale: 3, useCORS: true, backgroundColor:'#fff', scrollX:0, scrollY:0 })`
   - `const dataUrl = canvas.toDataURL('image/jpeg', 0.98)`

5) 清理离屏容器
   - `host.remove()`（放在 finally）

6) 返回 `dataUrl`

### 3) 不影响其他页面与正常使用的保障

- 全流程不再修改真实 `#roof-editor-grid/#roof-viewport` 的结构与可见性。
- 所有转换仅发生在：
  - `buildRoofSnapshotForPdf()` 的离屏 clone
  - `onclone(clonedDoc)` 的导出 clone
- 导出完成后清空：
  - `window.__pdfExportingPageNum = null`
  - `window.__pdfRoofSnapshotDataUrl = ''`

## Assumptions & Decisions

- “截图 1 的画布内容”作为输出基准：背景图保持原始宽高比、测距线与面积多边形必须可见、自定义组件的形状必须可见（不仅仅是文字）。
- 位图化优先级高于矢量精度；scale 默认 3（与现有一致），若文件体积过大再做优化。
- 不改变第 5 页编辑器的实际渲染与交互逻辑，只改导出路径。

  - 第 5 页画布中确保存在：自定义多边形、至少一条测距线、至少一个自定义组件（非 PV）。

## Summary

在现有单页应用（[index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html)）的“光储计算”页（`view-pvcalc`）内新增一个“当前视图”下拉选择，并增加新子页面 “TNB Calculator”。TNB Calculator 采用原生 JS + Tailwind（不引入 React / framer-motion），提供双模式（kWh→Bill / Bill→kWh）实时联动计算，包含分段电价、ICPT、ST 逻辑以及 Dead Zone 提示。

## Current State Analysis

- 项目形态：单文件静态应用，入口与全部 UI/逻辑集中在 [index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html)，使用 Tailwind CDN；没有 React 工程结构与依赖管理。
- 顶部主导航通过 `window.switchTab(tab)` 在多个 `main#view-*` 之间切换；“报价生成”页在自身内部有“当前视图”下拉（`#quote-page-select`）实现多页切换。
- “光储计算”页当前只有一个视图（光伏与电池系统测算），以静态 DOM + `window.calculatePV()` 实时更新结果。

## Decisions (Locked)

- 技术栈：沿用项目现状，使用原生 JS + Tailwind；不引入 React / framer-motion。
- 布局：TNB Calculator 使用单卡片 + Toggle 切换双模式（移动端/桌面一致）。
- Dead Zone（219.81–232.38）：仅提示，不计算、不更新 kWh 输出。
- 额外 Dead Zone（778.72–930）：同样仅提示，不计算、不更新 kWh 输出（原因：1500→1501 的 ICPT 跳变导致账单断层）。

### 3) 实现 TNB 计费核心逻辑（Forward + Reverse）

目标：严格按用户给出的分段与规则输出，并保证货币 2 位小数。

- 文件：[index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html)
- 新增/调整函数（均挂到 `window.*`，与现有模式一致）：
  - `window.tnbConstants`：
    - tiers：`[{ cap: 200, rate: 0.218 }, { cap: 100, rate: 0.334 }, { cap: 300, rate: 0.516 }, { cap: 300, rate: 0.546 }, { cap: Infinity, rate: 0.571 }]`
  - `window.getTnbIcptRate(kwh)`：
    - `kwh <= 600 ? -0.02 : (kwh <= 1500 ? 0 : 0.10)`
  - `window.calcTnbForward(kwh)`：
    - 逐段填充 tiers，得到每段 charge 与 `energyCharge`
    - `icpt = kwh * icptRate`
    - `st = (tier4Charge + tier5Charge) * 0.08`
    - `total = energyCharge + icpt + st`
    - 返回结构：`{ kwh, energyCharge, icpt, st, total, tierCharges: [...] }`
  - `window.calcTnbReverse(bill)`：
    - 处理边界与 Dead Zone：
      - 若 `219.81 <= bill <= 232.38`：返回 `{ deadZone: '600' }`
      - 若 `778.72 <= bill <= 930`：返回 `{ deadZone: '1500' }`
    - 按分段公式计算 kWh（严格使用用户给出的 breakpoints 与系数）：
      - `<= 39.60`：`bill / 0.198`
      - `<= 71.00`：`(bill - 39.60) / 0.314 + 200`
      - `<= 219.80`：`(bill - 71.00) / 0.496 + 300`
      - `<= 408.70`：`(bill - 232.39) / 0.58968 + 601`
      - `<= 778.71`：`(bill - 409.32) / 0.61668 + 901`
      - `> 930`：`(bill - 930) / 0.72468 + 1501`
    - 返回结构：`{ bill, kwh, deadZone: null }`
  - 格式化：
    - 货币统一用 `Number(x).toFixed(2)` 显示
    - kWh 统一保留 2 位（便于反算的非整数结果展示）

### 4) 交互与数据流（避免互相触发造成循环）

- 文件：[index.html](file:///Users/jqz/Library/CloudStorage/OneDrive-个人/Github%20Project/minova/index.html)
- 新增状态：
  - `window.__tnbMode`：`'kwhToBill' | 'billToKwh'`
  - `window.__tnbLastEdited`：`'kwh' | 'bill' | null`（用于决定用哪一侧输入驱动刷新）
- 事件绑定：
  - Toggle 切换：更新 `__tnbMode`，并调用 `window.recalcTnbFromActiveInput()`
  - `kWh` 输入 `oninput`：
    - 设置 `__tnbLastEdited = 'kwh'`
    - 调用 `calcTnbForward` 刷新 bill 与明细
  - `Bill` 输入 `oninput`：
    - 设置 `__tnbLastEdited = 'bill'`
    - 调用 `calcTnbReverse`
      - 若 dead zone：展示 tip + 清空/不更新 kWh 输出
      - 否则：输出 kWh，并可选用 `calcTnbForward(kwh)` 填充参考明细（若 UI 需要）
- 防循环策略：
  - 输出框使用 `readonly` 或非 input 的文本节点展示（避免 set value 触发反向 oninput）

## Assumptions & Compatibility

- “TNB Calculator” 仅在 `view-pvcalc` 内作为子页面，不新增顶层 Tab，不影响现有导航逻辑。
- 采用局部深色卡片样式，不切换全局 body dark mode，避免影响其他页面的视觉与打印/PDF 导出样式。
- Reverse 分段公式按用户给定直接实现；Dead Zone 不反解，避免给出不可靠近似。

## Verification Steps

1. 本地启动静态服务（按项目约定可使用 `python3 -m http.server`），打开页面。
2. 进入“光储计算”页：
   - 下拉选择“1. 光伏与电池系统测算”，确认原 PV 计算器可正常输入与更新。
   - 下拉选择“2. TNB Calculator”，确认新页面显示且不影响顶部导航。
3. Mode A（kWh→RM）验证：
   - 输入 `600`：ICPT 为 `-0.02`；ST 为 `0`（tier4+5 为 0）；Total 与分段金额符合期望。
   - 输入 `900`：ST 仅对 tier4 生效（0.546 段）；Total 正常。
   - 输入 `1500`：ICPT 为 `0`；Total 接近 `778.71`（允许 0.01 级别舍入差）。
4. Mode B（RM→kWh）验证：
   - 输入 `39.60` 输出约 `200` kWh。
   - 输入 `219.80` 输出约 `600` kWh。
   - 输入 `220.00` 显示 Dead Zone 提示，kWh 输出不更新。
   - 输入 `800.00` 显示 1500kWh 跳变相关提示，kWh 输出不更新。
   - 输入 `1000.00` 输出大于 `1501` kWh。
5. 数值展示：
   - 所有 RM 输出均为 2 位小数；
   - 切换模式与输入更新时，关键数字有轻量动效且不抖动、不影响输入焦点。

# 调整生成报价（PDF）逻辑与边距计划

## 1. 现状分析
- **页边距问题**：之前的 PDF 生成逻辑中为了“去边框”，通过 JS 将打印容器的 `padding` 强制设为了 `0`，这导致 Tailwind 原本设置的内边距（`p-12`）失效，从而让生成的 PDF 内容完全贴边，未能保持与网页上呈现一致的排版。
- **页面选择弹窗冗余**：目前点击“生成报价（PDF）”会先弹出一个专属的选择页弹窗，确认后再弹出原有的“认证文件选择”弹窗，操作流程繁琐，且 Quotation 没有强制锁定。

## 2. 具体修改方案

### 2.1 修复 PDF 边距（Margins）
- 修改 `generateQuotationPDF` 中 `html2canvas.onclone` 的样式注入逻辑：
  - 移除对每一个 `.quote-page` 及 `#pdf-content-wrapper` 的 `padding: 0` 强制覆盖。
  - 保留原有的 Tailwind `p-12 md:p-16`（这会转化为 PDF 的边距）。
  - 设置 `margin: 0 auto` 确保页面内容在 210mm 宽度下居中显示，完美还原网页视觉。

### 2.2 合并“附加页面”至认证文件弹窗
- 删除我之前添加的独立 `print-pages-modal` 相关 DOM 和 JS 逻辑。
- 将“生成报价（PDF）”按钮重新绑定到原先的 `openCertAttachmentModal()`。
- 在 `cert-attachment-modal` 的 HTML 模板内，顶部插入一个新的折叠区域：**【附加页面选择】**。
- **强制选择项**：在这个区域中，将第一页“1. 报价单 (Quotation)”设为 `disabled` 且默认 `checked`（必选项）。
- **新增快捷操作**：在该区域增加“全选”与“不选”两个小按钮，方便用户快速控制第 2~5 页的勾选状态。
- **联动统计**：修改原有的 `updateCertSectionCount` 和 `updateCertSelectedSummary` 逻辑，使其能够正确统计“附加页面”的勾选数量（如 4/4 项）。

### 2.3 生成前读取选择
- 修改原本的 `confirmAndGeneratePDF()`：在开始打包 PDF 之前，扫描模态框内的 `.print-page-checkbox` 状态。
- 收集选中的页面编号并更新 `window.selectedPrintPages`，确保 PDF 只渲染用户选中的部分。

## 3. 假设与决策
- **Quotation 固定选中**：第 1 页为核心报价，不允许取消，以防生成了一份毫无报价内容的 PDF。
- **全选/不选的范围**：只控制 2~5 页，因为第 1 页已被锁定为必选。
- **样式一致性**：通过保留 `.quote-page` 的 padding 并让其按 `border-box` 适应 `210mm` 宽度，保证无论哪一页在 PDF 中都有完全一致的内边距和背景色展示。

## 4. 验证步骤
1. 点击“生成报价（PDF）”按钮，检查是否直接弹出**一个**弹窗（即认证文件弹窗）。
2. 在弹窗中找到【附加页面选择】区块，确认“1. 报价单 (Quotation)”是置灰且已打勾的。
3. 点击“全选”/“不选”按钮，检查第 2~5 页的复选框状态是否同步变化，并且折叠栏右侧的“X/4 项”统计是否正确。
4. 勾选几页并附加几份认证文件，点击“确认生成”，等待 PDF 下载。
5. 打开下载的 PDF，确认页面四周拥有合适的留白（边距），与网页上的白色卡片显示完全一致，且未勾选的页面不会出现在 PDF 中。
